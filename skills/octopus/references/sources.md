# 话题研究来源策略

来源由主持模型的公开网页检索和 Octopus 平台适配器共同提供。网站名称是检索方向，不代表已经订阅、安装官方 API、具备登录权限或完成本次抓取。每次简报报告实际使用的来源。

来源随用户主题调整。下列科技与商业站点是默认兴趣的例子，不是唯一来源清单。旅行优先目的地官方资料和具体体验记录；教育优先教育机构、研究和实践资料；文化历史优先原始文献、档案和可靠研究；其他领域同样选择对应的一手资料。无需为每个话题遍历开发者社区或国内热榜。

## 核心事实与报道

- 海外：与主题相关的公司官方发布、产品文档、GitHub Releases、研究机构和论文原文。例如 OpenAI、Anthropic、Google DeepMind、Meta、Hugging Face 等的公开资料；不要求每次全部遍历。
- 国内：与主题相关的国内公司官方公告、产品文档、代码仓库和研究论文；公开可检索的科技/商业报道可从 36氪、虎嗅、机器之心、量子位等发现线索，再核对原始出处。
- 商业判断：优先有明确来源的客户案例、定价、产品可用性与公司披露；新闻稿或公司自述不能独立证明效果和需求规模。多篇通稿转载不算多重独立验证。
- 主持环境已经有联网工具时，直接用它检索及打开公开网页。Brave/Exa/Serper/Parallel 是引擎可选的搜索后端，不是内容来源，也不是必须另购的服务。

## 社区与平台适配器

| 平台 | 用途 | 入口及条件 |
| --- | --- | --- |
| GitHub | Releases、代码、Issues、PR、维护动态 | GitHub API；本机 `gh` 或 token 参与可用性判定，实际请求仍可能受权限和限流影响 |
| Hacker News | 开发者与创业者讨论 | Algolia HN API，无需单独密钥 |
| Reddit | 真实使用经验、故障、比较与讨论 | 公开抓取路径；可能受反爬和限流影响，ScrapeCreators 可作配置后的备选 |
| X | 发布方与使用者的即时反馈 | xAI API、明确提供的令牌或已认证 xurl；不自动读取浏览器会话 |
| YouTube | 演示、测评、视频字幕与评论 | `yt-dlp` 或已配置的 ScrapeCreators 路径；字幕不可用要如实说明 |
| TikTok / Instagram / Threads | 演示、创作者和传播信号 | 需要 ScrapeCreators 等对应配置；与 AI/商业问题无关时跳过 |
| 小红书 | 国内使用反馈、消费需求和案例线索 | 本机适配 xpzouying/xiaohongshu-mcp 的 HTTP 服务，需要服务可达、已登录，并显式选择 xiaohongshu；地址使用 `XIAOHONGSHU_API_BASE`，开启服务认证时另配 `XIAOHONGSHU_API_TOKEN`，不复用 X 的 `AUTH_TOKEN` |
| Bluesky / Truth Social | 特定社区补充 | 对应凭据；仅在主题相关且已配置时使用 |
| Digg | 讨论补充 | 需要用户自行安装 `digg-pp-cli` |
| Pinterest | 视觉和消费灵感 | 对应配置且显式请求；不纳入普通每日 AI 简报 |
| Polymarket | 与预测问题直接相关的市场预期 | 公共 API；普通 AI 日报不默认加入，不把赔率当已证实事实 |

Perplexity 是可选的额外检索/合成服务，需 OpenRouter 等配置，不视作独立一手证据。采用其线索时仍应打开原始引用核验。

发布版提供微信公众号、微博、知乎和 B 站的可选采集入口，但不包含已配置的服务或登录状态；国内抖音尚未接入。接入不代表全站覆盖，也不是平台授予的官方开放 API。

## 覆盖与状态

区分“代码支持”“有配置/工具”“本次检索成功”三个状态。只读配置存在性时不显示值；不要为盘点来源而运行 setup、扫描 Cookie 或连接新账号。

每日 manifest 中记录来源或具体站点的 `source`、实际 `status`（ok/empty/error/unavailable）与 `required`。required 根据本次主题和地区范围确定；综合国内外简报要求两侧事实检索，限定地区的研究则以相关地区的核心来源为准。可选社区未配置时记录缺口，不阻塞能够完成的工作。

来源的 zero results 仅说明这次检索没获得条目，不证明没有新闻。required 来源失败或未配置的运行应标 partial，不能把完整完成的时间向前推进。

## 可选国内来源

安装与登录按本目录 [本地来源配置](local-sources.md) 执行。只在用户明确要求配置时进行，不在普通研究中自动安装。`local-sources/` 发布的是客户端和启动器；`runtime/`、服务本体和登录状态均不在发布包内。

- 小红书：使用用户自己运行并登录的 xiaohongshu-mcp。默认有界面模式；列表不保证提供正文或准确时间。搜索仅提供发现线索的粗时间范围，不能宣称完整覆盖指定 30 天。
- 微信公众号：WeRSS 加用户扫码授权的微信读书会话；公众号列表由用户设置，默认没有任何账号。返回结果不保证完整历史，日期须回到原文核验。
- 微博：RSSHub 扩展 `/local-weibo/hot`，仅公开热搜线索，不代表完整正文和评论。
- 知乎：RSSHub `/zhihu/hot`，问题创建时间与新闻发生时间分开处理。
- B 站：示例为 RSSHub `/bilibili/ranking/tech` 科技区排行榜，可由用户调整路由；视频信息不等于字幕或音频转写。

相关来源已配置后，显式选择平台：

```sh
python3.12 "$skill_dir/scripts/domestic_sources.py" --sources weibo,zhihu --output "$run_dir/domestic-candidates.json"
```

选公众号且需要更新时可加 `--sync-wechat`。该脚本的 `--sources` 与原引擎的 `--search` 参数不同，不向引擎传入未支持的平台名称。来源入口会等待服务就绪，完成、普通失败、超时或正常取消时清理本次进程。强制结束 AI 助手应用程序、操作系统崩溃等情况不属于已保证的清理路径。

`candidates` 是待核验材料；`coverage` 记录本次实际结果。`topic_matches` 使用用户配置的关键词，默认关键词为空，不丢弃未命中的条目。热榜时间与 WeRSS 提供的待核日期不能伪装成精确的新事件时间。

服务平时停止是正常状态；只有本次启动或请求失败才记录缺口。未配置的来源跳过，用相关公开网页补充并说明覆盖。不得自行导入浏览器会话、设置登录自启动或常驻任务。
